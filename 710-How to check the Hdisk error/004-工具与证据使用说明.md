## 二、只读采集脚本怎么用
### 1. 运行位置与前置条件
在要检测的Mac本机终端执行，Python3必须已存在；脚本只支持macOS和APFS。先运行 `hostname`，确认目标身份。

下面命令假定已进入本目录；把 `实际主机名.local` 换成目标Mac的真实输出。新证据目录必须不存在，脚本会拒绝覆盖旧资料。疑似故障盘上有重要资料时，把输出目录改到另一块健康介质。

```sh
python3 ./工具/collect-mac-storage.py \
  --expect-host '实际主机名.local' \
  --output "$HOME/storage-check-$(date +%Y%m%d-%H%M%S)"
```

默认只采集身份、磁盘布局、供电；如果PATH中有smartctl且物理盘映射明确，也会读取健康页。仅写证据目录；正常系统自身的后台写入不受它控制。

### 2. 加上在线校验和限定日志
接电、保存工作，接受在线校验可能短暂卡顿后，显式添加参数：

```sh
python3 ./工具/collect-mac-storage.py \
  --expect-host '实际主机名.local' \
  --output "$HOME/storage-verify-$(date +%Y%m%d-%H%M%S)" \
  --verify --logs
```

`--verify` 检查数据卷及其实际容器，不运行修复。`--logs` 只查询最近一小时的若干kernel错误词。需要其他APFS卷时，使用 `--volume '/Volumes/目标卷'`；不支持的文件系统会停止，不猜测命令。

可用 `--smartctl '/可信位置/smartctl'` 指定已有工具。脚本不会自动下载或安装。多个物理存储时，脚本不替用户猜一个物理盘读取SMART。

### 3. 保护条件和结果解释
- 主机名不匹配时，在创建输出目录前停止。
- 从实际plist读出APFS容器、物理存储、卷UUID，不固定disk0/disk3。
- 每次校验前复核卷UUID及设备标识，变化就中止后续校验。
- 每条命令分别保存stdout、stderr、开始/结束时间和退出码。
- `manifest.json` 摘录待看的警告行，但不能代替完整日志。
- `sha256.json` 用于核对已保存文件是否变化。

**脚本退出0只表示所选采集命令执行完成，不等于磁盘健康。** 即使检测到warning，底层命令也可能返回0；由人结合全部证据判读。返回1表示至少有命令未完成或身份检查中断；返回2通常表示参数或保护条件不满足。超时后不能假设所有系统辅助进程都已退出，不立刻叠加重跑。

此次工具验证运行了帮助、身份不匹配拒绝、新目录基础采集及既有目录拒绝覆盖等检查；没有在编写资料时执行新的 `--verify`、修复或大文件写入测试。

## 三、历史写入源码怎么复用
### 1. 固定参数与实际覆盖范围
该源码来自目标机当时已成功运行的原件，SHA-256与旧证据一致。固定每轮32GiB、两轮不同种子，顺序完整读回，再做8192次4KiB随机验证。使用F_NOCACHE、fsync和F_FULLFSYNC；内存缓冲区约16MiB。

程序要求初始空间至少达到“32GiB文件＋80GiB预留”，约112GiB；小盘或空间不足会拒绝。80GiB是本次程序的保守固定值，不是Apple规定的通用门槛。

源码自身不检查供电、不确认主机名，也不自动备份。调用者先确认：目标电脑正确、接电、资料允许测试、后台任务可暂停。只在自己新建的目录运行，不传入已有资料路径。

### 2. 编译与执行
需要已安装的C编译器；没有编译器就先停在这里，不为了复制命令默认安装整套开发环境。

以下命令在本目录运行；会创建独立目录并产生真实写入：

```sh
test_dir="$(mktemp -d "$HOME/ssd-filetest.XXXXXX")"
if cc -O2 ./工具/历史目标机-32GiB双模式校验.c -o "$test_dir/ssd-test"; then
  "$test_dir/ssd-test" "$test_dir/test-data.bin" > "$test_dir/result.log" 2>&1
  test_rc=$?
  printf '%s\n' "$test_rc" > "$test_dir/exit-code.txt"
  printf 'Results: %s\n' "$test_dir"
fi
```

成功会打印两条RESULT、随机验证结果以及 `COMPLETE passed=true temporary_data_removed=true`，并删除自己创建的测试数据文件，保留程序与结果日志。失败时不要把错误码当通过，也不要立即删除现场；程序可能留下很大的测试文件，先保存日志、确认路径后再清理。

不自动把所有错误归因于SSD：读回不一致也需考虑内存、控制器与软件环境。该程序的生成/比较算法相同，属于实用数据完整性检查，不是经过独立认证的专业硬件诊断套件。

### 3. 为什么不附一个自动修复或抹盘脚本
急救、卸载卷、恢复模式启动、重新建卷涉及目标选择和可用性变化。仅靠旧编号自动执行容易修错层级。这里保留人工识别、逐步处理、重启复查的流程；确需抹盘时另核对机型、目标范围和清空授权。

## 四、证据副本与哈希
`来源与SHA256.json`（原库附件/证据，未包含在本测试包） 记录每个关键副本的原始路径和哈希。副本经过逐文件比较；旧760项目归档没有改写。

| 子目录 | 保存内容 |
| --- | --- |
| 修复前 | 数据卷/容器在线日志、分区表、fsck手册与当次完成记录 |
| 读写测试 | 原始SMART JSON、两轮写入校验输出、驱动前后计数与相关日志 |
| 恢复模式照片 | 数据卷详细日志、显示所有设备、容器完成页 |
| 修复后 | 同一卷身份、数据卷和容器校验及命令退出记录 |

本目录保存精选证据，不复制全部私人目录或工具二进制。原件包含设备标识、内部IP或路径，对外发送先检查。哈希一致只证明复制无变化；没有独立硬件签名、没有为采集前历史背书。

## 五、权限和远程边界
脚本不会调用sudo、关闭FileVault或改组成员。smartctl在本次目标机上普通账户可读，但其他机器不保证；原始设备读取权限又是另一回事，不能混为一谈。

远程使用时，先把脚本传到已核实身份的目标机，再明确在远端运行；不要在控制电脑执行完，把控制电脑的结果标成目标机的结果。本次文档编写只在控制电脑做基础采集工具验证，没有连接<目标机>/<备用机>执行新检测。
