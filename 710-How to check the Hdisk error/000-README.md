## 一、先确定要解决什么
**先保护资料，再判断异常属于文件系统、存储硬件还是连接链路；修复必须以重启后复查作为收尾。**

日常说的“硬盘坏了”，可能只是目录或元数据不一致，也可能是 SSD、控制器、外接线缆或硬盘盒的问题。磁盘急救处理文件系统结构；它不能把损坏的 NAND 或接口修好。

这套资料没有把“绿色勾号”“退出码 0”“SMART 正常”当作无故障证明。每项检查都写明能确认什么、还没覆盖什么。

## 三、这次已经验证的经验
1. `fsck_apfs` 默认允许仅有警告时退出 0；完整日志比最后一行更重要。
2. 数据卷急救提示查整个容器时，要对正确的主 APFS 容器继续操作。
3. `macOS Base System` 是恢复环境；本次它位于另一个小容量磁盘映像容器，不是要修的内置数据盘。
4. `disk3`、`disk5` 只是当次编号。每次重启或换环境后重新识别，不能照抄旧案例。
5. 32GiB 文件重写两轮等于累计写入 64GiB，不等于覆盖 64GiB 不同物理闪存，更不是全盘物理检测。
6. 18:10 的旧警告不能用来否定 18:20 的后续修复；照片、命令和结果要按时间对齐。
7. 本次最终成立的证据是：同一数据卷 UUID，修复后重启，两项只读复查均无原警告。
