## 一、实施前准备
先选一台 Windows 笔记本和一台 Mac 笔记本作为试点。登记机器名、系统版本、使用者、本地工作目录、当前 Codex 版本、代理入口、外出时使用的网络、到 Mini4 的远程通道，以及最近一次真实模型调用时间。登记表不写密码和完整节点参数。

把配置分成三份：①所有设备共用的代理规则与启动行为；②Windows/Mac 各自的安装和更新步骤；③每台机器独有的工作目录、设备 ID、权限和登录状态。Mini4 只发布前两类及经校验的非敏感机器参数。Codex 的 `config.toml`、认证状态位于各机的 `CODEX_HOME`；不要把整个目录同步到多台电脑。→ [OpenAI Docs · 配置位置](https://learn.chatgpt.com/docs/config-file/environment-variables)

美国节点准备一个由自己控制的固定域名。先核对现行 Reality 客户端的 `server`、`servername`、端口与密钥参数；域名应解析到当前服务器 IP。换 IP 只改 DNS 的前提是服务器协议、端口和密钥不变。

## 二、先做两台试点
### 2.1 本机能力
在 Windows 和 Mac 各选一个**测试目录**，让本机 Codex 读取一份测试文档、创建一份新文档，再核对磁盘上的内容。随后各做一项低风险的软件版本查询，确认命令确实在目标机执行。软件安装与卸载先用可恢复的测试软件演练，并观察权限提示；不要用系统关键软件做试验。

Windows 优先沿用 900 项目的原生安装方案；Windows 11 原生沙箱是官方推荐基线，当前兼容机器可优先验证 MXC。Mac 保持本机沙箱和审批设置。任何需要管理员权限的安装或卸载，都要在目标机完成操作系统授权。→ [OpenAI Docs · Windows 沙箱](https://learn.chatgpt.com/docs/windows/windows-sandbox) · [权限](https://learn.chatgpt.com/docs/permissions)

### 2.2 用量采集
先在两机各发起一轮短任务，记录任务前后的 `/status` 会话 token 数，并检查所选采集源是否产生可关联的用量事件。优先评估官方遥测中的 `response.completed` token 字段；如当前 CLI 传输方式没有稳定产生该字段，再验证 app-server 线程用量事件或本机会话记录。**不能先定脚本再假定字段始终存在。** → [OpenAI Docs · 遥测事件](https://learn.chatgpt.com/docs/agent-approvals-security) · [app-server 线程事件](https://learn.chatgpt.com/docs/app-server)

采集程序只存必要的结构化摘要：`device_id`、事件唯一键、开始/结束时间、模型、输入/输出/合计 token（以实际返回字段为准）、采集版本。若只能得到合计，就只报合计，不推算输入/输出。Mini4 按 `device_id + 事件唯一键` 去重，并保留最后上报时间。采集涉及对话或工具输出的源文件时，只提取计数，不能把完整源文件上传。

让笔记本断开 Mini4 通道后再做一次任务，确认记录仍留在本机；恢复通道后补报同一批数据两次，Mini4 汇总不得重复增加。若离线期间无法使用 Codex，先排查模型网络出口，不要把 Mini4 上报通道误认为 Codex 必需链路。

### 2.3 外出链路与换 IP
用真实手机热点测试笔记本到美国节点的 Codex 请求、到 Mini4 的小文件/摘要上报，两条链路分别记录成功与耗时。Mac Air 可先验证现有覆盖网络；Windows 接入前需建立并验证自己的安全通道。Mini4 只能出网时，不保证外部主动连入；若通道不稳，离线队列照常保留，回到家或备用通道恢复后补报。

在节点 IP 切换演练中，先保留旧地址可回退，更新测试域名的 DNS 记录，等待解析生效并确认出口地址，然后从两机各发起一次真实 Codex 请求。仅看 DNS 返回或代理端口监听，不算验收通过。

## 三、逐台接入
1. 在目标机核对系统、磁盘和本地工作目录；按 900 手册或 Mac 现行安装方法装 Codex CLI，确认 `codex --version`。
2. 在目标机用它自己的 ChatGPT 登录流程授权；用 `codex login status` 确认本机状态，再发一条真实短请求。不要复制另一台机器的登录文件作为常规部署办法。→ [OpenAI Docs · 登录](https://learn.chatgpt.com/docs/auth?surface=cli)
3. 部署本机代理配置，保留国内系统直连规则。启动脚本只为 Codex 进程提供需要的代理环境，避免无意改变所有软件的出口。节点地址使用已验收的固定域名。
4. 安装用量采集与本地待发送队列，为机器分配稳定设备 ID；上报到 Mini4 的凭据按机器分别发放和撤销，不与 ChatGPT 凭据混用。
5. 首次同步后，在 Mini4 登记该机版本、最近成功模型调用、最近上报时间和未发送条数。笔记本断网重试不得妨碍本机 Codex 启动。

**单机验收：** 本机测试文件可读写；软件查询命令在本机执行；真实模型请求成功；Mini4 上只出现这台机器的一份用量；断线记录可补报且不重计；客户端没有收到其它机器的私有配置。

## 四、日常使用和统计
用户在本机打开 Codex，进入要处理的本地目录，提出文档管理或软件操作任务。需要管理员权限时，在该机确认。`/status` 用于看当前会话，`/usage` 用于看账号级 token 活动和额度；Mini4 报表按 `device_id` 汇总本机采集的事件，不把三种口径混为一谈。→ [OpenAI Docs · CLI 命令](https://learn.chatgpt.com/docs/developer-commands)

Mini4 看板最少显示：机器名、系统、Codex 版本、最近成功上报、最近真实模型调用、当前待发送数、当天/本周 token 合计和采集是否完整。某机离线时显示“数据截至某时”，不把旧值显示成当前值。不同机器共用一个 Plus/Pro 账号时，账号额度仍共用；其它设备或 ChatGPT 产品的用量可能让账号总量大于本项目机器合计。→ [OpenAI Docs · Codex 用量](https://learn.chatgpt.com/docs/pricing)

## 五、美国服务器换 IP
### 5.1 仅 IP 变化，节点参数不变
1. 在服务器管理面板或可信管理通道确认新旧 IP、协议、端口和服务仍有效。
2. 更新固定域名的 A 记录；保留旧记录及回退办法至验收完成。不要把新 IP 直接散写到每台机器。
3. 从 Windows、Mac 各确认域名解析和代理实际出口，再各发一条真实 Codex 请求；观察现有连接和 DNS 缓存的切换时间。
4. 记录切换时间、真实调用结果、失败机器及回退记录。ChatGPT 账号不变，无需重新登录。

### 5.2 协议、端口或密钥也变化
Mini4 生成候选配置，逐台先做语法检查和独立实例测试，再发布。客户端保留上一版；新配置的真实模型调用失败时回滚。敏感节点参数只通过受控配置通道传输，不写入本项目或聊天记录。参照 [900 · 换节点与回滚](../900-windows%20computer%20use%20codex%20and%20claude/020-%E7%BB%B4%E6%8A%A4%E6%8E%92%E9%9A%9C%E4%B8%8E%E6%8D%A2%E5%8F%B7%E6%8D%A2%E8%8A%82%E7%82%B9.md)。

## 六、更新与故障恢复
Mini4 发布带版本号和校验值的更新清单；笔记本在线时**主动拉取**，先备份本机旧配置，再验证新配置，最后切换。离线设备下次上线补更新。软件安装/卸载任务仍由目标机执行，涉及管理员权限时按该机系统提示处理；管理通道本身不应拥有不受限的系统权限。

排障先分四层：①目标机 Codex 能否本机启动；②代理能否连到美国节点；③能否完成真实模型请求；④用量能否到 Mini4。第四层失败只影响报表，不应阻止前三层。若两机同时失败，查公共节点与 DNS；只有一机失败，查该机代理和登录；模型正常而报表落后，查覆盖网络、本地队列与接收端去重。
