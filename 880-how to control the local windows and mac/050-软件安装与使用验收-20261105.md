## 二、部署方式与本次新经验

- 优先检查已装软件、系统架构、实际登录用户和桌面 session。当前是 Windows 10 专业版 x64，Administrator 的桌面 session 为 5。
- Mac 从官方渠道代下完整安装包，验证 PE 格式并记录 SHA-256；SCP 后在 Windows 再次核对哈希及 Authenticode 签名。安装路径、文件版本与实际启动分别核验。
- 使用 `Interactive` 计划任务进入当前用户桌面。安装通常需要 Highest；应用启动与 OneDrive 使用 Limited，不能把 session 0 的安装成功当作桌面可用。
- 以 Windows API 进行 DPI aware 截图、枚举窗口，在不部署远程桌面的条件下独立确认实际画面。仅有进程存在不算完成验收。
- Obsidian 初始 `obsidian.json` 使用无 BOM UTF-8。首次有 BOM 的配置未自动进入测试库；备份后改为无 BOM 并用官方 Obsidian URI 打开测试笔记，实际成功。此结论只覆盖本次实测，未断言所有版本都受影响。
- 微信输入法外层 NSIS `/S` 的退出码 0 只证明机器文件已部署。本次仍需打开随附的 `wetype_installer.exe`，点击官方“安装”按钮完成首次用户启用。官方随附启用程序实际选择了 3.0.0.38，覆盖初始 3.0.2.29 的当前版本登记；最终交付按实际运行版本记录，不把初始安装包版本当作最终版本。等待安装完成后，InputMethodTips 出现 `0804:{86598FB9-66A2-463E-B9C2-AEB906D477AD}{607FDF85-FCC8-4DBD-A365-41296F980C9C}`，并通过实际拼音上屏验收。
- 计划任务直接启动微信输入法的子进程曾带 `--restricted`；通过资源管理器启动官方快捷方式后不带此参数。设置窗口随后正常显示；这个现象不能单独证明故障根因，须结合首次启用步骤判断。
- 中文输入应在同一交互任务里连续完成“键入拼音 → 候选截图 → 空格提交 → 保存 → 读回”。分开任务可能打断组合状态；验收结果还应在任务结束后读取，避免把上一轮文件当作当前结果。最终 `input-result.json` 的 Text 精确等于“测试”。
- Dynalist 与 OneDrive 不复制其他设备的账号 token；安装成功、登录界面正常与账号同步成功是三个不同层级。
