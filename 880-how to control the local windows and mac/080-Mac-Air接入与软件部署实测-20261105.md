## OpenCode 的可复用做法

官方来源：[v2.2.5 发布页](https://github.com/anomalyco/opencode/releases/tag/v2.2.5)。使用 `opencode-darwin-arm64.zip`，当次 GitHub 官方资产 digest 为：

```text
25ba9908979fa7d764792c82589b4b5768ab1511154e0317d98aa77d216ce767
```

注意：此前对话中出现过其他发行版本的哈希，不能用于此包。每次按具体 tag 和资产重新取 digest。

安装目录为目标用户 `~/.opencode/bin`。修改已有 `.zprofile`、`.zshrc` 前备份，追加该目录到 PATH，并验证：

```sh
zsh -lic 'command -v opencode; opencode --version'
opencode --help
```

本次通过 `open -na Ghostty --args -e /Users/<用户名>/.opencode/bin/opencode` 启动，观察到 Ghostty → login → opencode，以及 opencode 后台服务。此验证证明程序能在 Ghostty 中启动；手工键入、画面渲染和模型回答不是同一层验收。

## 微信输入法的关键技巧

安装包复制到系统目录后，应用存在、主进程运行，并不保证已启用。此前在 SSH 中调用 TIS 注册/选择即使返回 0，桌面也未据此确认切换。

本次在 `gui/501`（当次控制台用户 <用户名> 的 UID）加载一次性 LaunchAgent，运行 JXA 调用 Carbon Text Input Source 接口：

1. 注册输入法目录：TISRegisterInputSource。
2. 枚举输入源：TISCreateInputSourceList。
3. 仅启用并选择拼音模式：TISEnableInputSource、TISSelectInputSource。
4. 在同一桌面会话读回 TISCopyCurrentKeyboardInputSource。

读回 ID 为 `com.tencent.inputmethod.wetype.pinyin`，主进程也已启动。父级 `com.tencent.inputmethod.wetype` 不是此次应选择的拼音模式。任务完成后已经 bootout 临时 LaunchAgent；未将它配置为登录常驻。

SSH 中 `defaults read com.apple.HIToolbox` 当时仍显示旧列表；它不能替代桌面会话的当前输入源读回，也不能证明重登后设置已持久化。下一步应在文本编辑器中键入拼音、选择候选并保存中文，再做重登测试。

## 下载与权限的经验

- 完整性优先：本次多份大包曾截断。使用断点续传仍须重新核对官方哈希和压缩/DMG 校验，不能凭大小相近安装。
- 区分校验环境：控制端出现多个应用验签异常，目标机原生 codesign 验证通过。不能把控制端异常直接归因于安装包恶意或损坏。
- 不夸大根因：代理、旧下载地址和续传都曾被怀疑；没有足够证据将下载损坏唯一归因于某一项。最终微信包使用 cask 指向的腾讯官方新地址并精确匹配哈希。
- SSH、管理员权限、隐私授权与 GUI 会话独立。密码不写入脚本或文档，不设置通用免密 sudo。TCC 权限按需授权。
- URL 必须完整复制，不能将省略号当成地址。临时服务失效后应重新生成/验证入口，不直接重放历史命令。
