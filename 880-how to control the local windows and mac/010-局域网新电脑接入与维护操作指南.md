## 一、推荐的工作方式

先建立 SSH 管理通道，再安装软件；需要看界面时另行接入桌面。用户负责新电脑上的首次运行、管理员授权与个人账号登录，AI 负责准备接入包、核验连接、部署和排查。

基本路径：

```text
AI 准备本次脚本 → 复制到 Air → Air 提供临时下载地址
                                   ↓
新电脑下载 → 用户运行并授权 → 开通 SSH → AI 接手维护
```

AI 可能实际运行在 mini4。此时下载入口仍放在用户面前的 Air；管理连接可从 Air 发起，也可由 mini4 经 Air 跳转。必须先确认 AI 当前在哪台机器上，不能把 mini4 的地址当成 Air 地址。

## 二、接入前准备

准备新电脑的系统类型、机器名称、登录用户名、当前 IP，以及要安装的软件。管理员密码只在新电脑本地输入，不需要发到聊天里。

两台电脑插电并保持唤醒。接入同一 Wi-Fi 后仍要实际验证能否互访：访客网络、酒店网络和企业无线网络可能隔离设备。地址不同或网段不同，也不能直接推定一定不可达。

AI 核对 Air 的实际网卡和 IP，生成当天下载地址。下载地址形如 `http://<Air当前IP>:<本次端口>/<文件名>`，以当次给出的完整地址为准。

## 三、Windows 如何接入

先区分两种电脑：

| 目标状态 | 接入包需要做什么 |
|---|---|
| 全新电脑，尚无 SSH 服务或管理公钥 | 安装或启用 OpenSSH Server、启动服务、配置公钥与访问规则 |
| 以前维护过，SSH 和公钥已存在 | 检查现有配置，按需要补充访问规则，避免重复安装 |

**首选：一条命令接入。** AI 在 Air 准备仅面向目标机的临时下载入口，提供一条明确要求在 CMD 中运行的短命令。命令形态如下，地址必须使用当次实际提供的值：

```cmd
curl.exe -fO http://<Air当前IP>:<本次端口>/w.cmd && w.cmd
```

用户运行命令后确认一次 UAC；入口下载本次 PowerShell 载荷、核对 AI 提供的 SHA-256 后以管理员权限运行。脚本自动回报结果，AI 自行取得用户名并连接。回报失败时才需要用户提供错误信息。文件应保存到可写且不含旧入口的目录；`&&` 确保下载失败不会继续执行。短命令适用于已检查的本次入口，不应换成来历不明的远程脚本。

**备用：浏览器下载。** CMD 下载不可用时使用下面原流程：

1. 用浏览器打开 AI 给的 Air 下载地址，下载压缩包并解压。
2. 运行当次生成的 `.cmd` 入口，核对用途并允许管理员提示。
3. 等待脚本输出机器名、用户名、IP、服务状态和成功或失败信息。
4. 将结果告诉 AI；失败时保留报错内容，由 AI 判断原因。

脚本使用公开 SSH 密钥来授权控制端，私钥留在控制端。Windows 管理员账户的公钥路径与普通账户不同，需要按实际账户和 SSH 配置处理。→ [Microsoft：Windows OpenSSH 配置](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh-server-configuration)

连接通了以后，软件安装可能还会弹出窗口。<伙伴A>案例证明 Windows SSH 会话与用户桌面会话不同，部分安装和界面验证需要在用户的交互桌面里执行。→ [030-<伙伴A>案例与源码出处](030-%E5%8E%86%E5%8F%B2%E6%A1%88%E4%BE%8B%E4%B8%8E%E6%BA%90%E7%A0%81%E5%87%BA%E5%A4%84.md)

## 四、Mac 如何接入

首次建议采用“系统设置开启远程登录 + 初始化脚本配置公钥”的办法。先让一台新 Mac 跑通，再考虑把更多步骤合并到脚本中。

用户现场步骤：

1. 在新 Mac 打开「系统设置 → 通用 → 共享 → 远程登录」，开启服务，并只允许本次使用的指定用户。
2. 从 Air 下载当次初始化包。首次建议按包内说明从终端运行，不依赖双击 `.sh` 的系统关联。
3. 脚本在正确用户的家目录中追加控制端公钥，修正 `.ssh` 和 `authorized_keys` 权限，并输出连接信息。
4. AI 从控制端验证真实 SSH 登录和文件传输。

macOS 对远程用户访问受保护文件提供单独的磁盘访问选项；只在任务确实需要时开启并验证。不能承诺所有系统权限都由脚本自动处理。→ [Apple：允许远程电脑访问 Mac](https://support.apple.com/guide/mac-help/mchlp1066/mac)

需要你远程看桌面时，在同一「共享」页面开启「屏幕共享」，限制允许访问的用户；已有远程管理配置时先检查冲突。现有 Air 可使用“屏幕共享”应用连接新 Mac。→ [Apple：打开或关闭屏幕共享](https://support.apple.com/guide/mac-help/mh11848/mac)

屏幕共享是你操作新 Mac 的通道。AI 是否能截图、点击，要看目标端是否另有可用工具及对应权限，必须另测。2026-11-05 已在 MacBook Air M1 验证 SSH、公钥授权、文件传输和应用部署；尚不能据此宣称所有桌面操作均可自动完成。实测与待验收项目见 [080-Mac-Air接入与软件部署实测-20261105](080-Mac-Air%E6%8E%A5%E5%85%A5%E4%B8%8E%E8%BD%AF%E4%BB%B6%E9%83%A8%E7%BD%B2%E5%AE%9E%E6%B5%8B-20261105.md)。

终端命令必须提供完整可复制地址，不用省略号替代 URL。临时下载服务可能已关闭，旧命令复用前先由 AI 检查服务、控制端 IP 和目标 IP。Mac CLI 安装后需在目标用户的登录/交互 shell 中检查 PATH；输入法设置应在桌面用户会话中操作，不能只看 SSH 会话返回值。

## 五、连接之后由谁做什么

| 工作 | 主要负责者 |
|---|---|
| 核对当前地址、生成脚本、提供下载地址 | AI |
| 首次运行、管理员密码、系统授权 | 用户 |
| 环境摸底、下载和安装软件、配置、查日志 | AI |
| 软件账号登录、设备码确认、购买与支付 | 用户 |
| 真实启动、关键功能验收 | AI 执行；必要界面步骤由用户配合 |
| 整理安装结果、连接方式和恢复方法 | AI |

SSH 登录成功不代表可以无需密码运行所有管理员操作。Mac 的 `sudo`、Windows 提权安装都要单独确认执行方式，不能默认授予永久免密管理员权限。

## 六、常见问题怎么判断

| 现象 | 优先检查 |
|---|---|
| 下载地址打不开 | 下载服务是否还在、Air IP 是否变化、网络是否隔离、端口是否监听 |
| 下载成功但脚本失败 | 管理员权限、系统与架构、是否用了旧电脑的专用脚本 |
| SSH 连接超时 | 路由、设备隔离、目标唤醒状态、访问规则是否仍绑定旧 IP |
| SSH 连接被拒绝 | SSH 服务是否运行，22 端口是否实际监听 |
| 公钥认证失败 | 用户名、公钥所在账户、文件路径与权限、SSH 配置 |
| SSH 能用但安装或界面操作失败 | 管理员权限、交互桌面、隐私权限、安装器日志 |
| 端口探测成功但 SSH 卡住 | 获取实际 SSH banner，并尝试真实认证；检查代理接管 |
| 昨天能连、今天不能 | 两端 IP、当前网络、临时规则是否到期、电脑是否睡眠 |

不要仅凭 ping 成败判断连接，也不要看到端口通就宣布部署成功。

## 七、维护结束与下次连接

维护开始前确定本次是临时连接还是持续维护。临时规则应说明到期时间，持续维护则记录密钥归属、允许账户、访问范围和撤销方法。

**长期授权与下载链接有效期必须分开说明。** 2026-11-05 案例中下载入口约两小时有效，SSH 公钥授权不设到期时间。关闭入口后仍可通过 SSH 连接，不需要每次重跑初始化命令。长期可达还依赖目标机开机、联网、未休眠和来源地址规则匹配；「无到期时间」不等于任何状态下都在线。

关闭临时下载服务与撤销 SSH 管理权限是两件不同的事。下载服务结束以后，已经配置好的 SSH 访问不一定同时消失。

换网络或 IP 后重新核对访问规则；不要默认沿用<伙伴A>案例的地址。结束时由 AI 留下软件版本、验证结果、配置备份位置、连接与撤销说明。
