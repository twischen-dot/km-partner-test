## 一、先确认执行位置与授权范围

先读本目录 README 和案例，确认当前 AI 所在机器。涉及本机工具链和跨机操作时，按用户 AGENTS.md 读取长期记忆索引，再筛选相关条目；长期记忆库只读。

确认当前控制端、目标机系统与架构、用户名、IP、是否已有 SSH、软件清单，以及连接保留方式。已有上下文能够确定的事项不要重复询问。

用户让你准备接入包、安装调试，意味着可以完成必要的可逆准备与部署；按实际工具权限处理提权，不将系统授权或审批限制解释为可绕过的步骤。

验收：能明确说出“脚本在哪里生成、从哪里下载、由哪台机器连接到哪个用户”。

## 二、准备本次接入包

### 首选交互：短命令 + 自动回报

用户已明确希望少参与、长期管理、不需要远程桌面时，直接沿用这些要求。优先检查目标 22 端口、读取 SSH banner 并尝试既有密钥，不预先重装 SSH。

2026-11-05 实测顺序：

1. 在正确控制端建立工作目录，生成专用管理密钥；私钥不进入下载目录。
2. 本地核对目标路由使用的源 IP。读取现有 sshd 有效配置，不默认管理员公钥路径。
3. 提供限定下载来源、禁止目录浏览、有截止时间的短 `.cmd` 入口；入口再下载并核对本次 PowerShell 载荷的 SHA-256，请求 UAC 后执行。
4. 载荷备份现有公钥内容与 ACL，幂等追加公钥；按 SID 配置 ACL，适配中文系统。保留原有 SSH 配置与其他密钥。
5. 通过本次随机路径回报 JSON：状态、机器名、实际用户名、服务启动类型、公钥路径、主机指纹、备份位置、本次新增规则；失败也回报具体原因。
6. AI 读取回报后直接连接，验收管理员 token 和 SCP 哈希一致性。验收后关闭两个临时入口，不撤销长期公钥。

短入口本身也必须属于 AI 已检查的本次自有文件；载荷哈希只能证明载荷与指定版本一致，不能把同一 HTTP 渠道中的内容自动称为可信来源。来源 IP 限制也不是设备身份认证。

**本次代码还不是通用安装器**：它要求目标已有 sshd，使用固定日期和本次地址，服务启动类型只设为 Auto，未配置故障恢复。新机器需重新生成参数，不能复制旧命令后假定通用。


在控制端建立按日期和机器区分的工作目录。建议包含 Windows 的 `.cmd` 入口与 PowerShell 载荷，或 Mac 的 `.sh` 入口，以及说明、文件哈希和本次参数清单。不要提前把这些建议文件名描述为已经存在。

需要参数化：目标标识、允许的控制端 IP、公钥、管理用户名、有效期、日志与回滚文件位置。IP 必须现场查询，不能复制<伙伴A>旧值。

脚本要求：

- 先检查系统、架构、目标用户和现有服务，再进行必要修改。
- 可重复运行：不重复追加公钥，不覆盖用户已有 `authorized_keys` 或 SSH 配置。
- 记录创建了哪些规则、服务变更、任务和配置备份，以便只撤销本次改动。
- 出错输出实际原因和退出状态；不能吞掉错误后显示成功。
- 包内可以有控制端公钥，不含控制端私钥、登录 token、代理凭据或管理员密码。
- 安装包核实官方来源及适用架构；校验值随版本核实，不能沿用旧版本哈希。
- 下载到本地、检查内容后执行，不把未知 HTTP 内容直接管道交给解释器。

Windows 接入包默认将本次新增访问规则限制到本次控制端。新增窄规则不覆盖已有宽规则，必须另外审查并如实记录，不能据此宣称目标全局只允许该来源。Mac 的远程登录用户限制与源 IP 限制是两回事，不得声称系统共享面板已自动实现源 IP 白名单；若任务要求源 IP 限制，先评估现有防火墙方案并单独验证，不默认改写系统 PF。

验收：复查脚本的实际副作用、目标参数和撤销步骤；有测试机时演练，否则明确标为待目标机首次验证。

## 三、分别实现 Windows 与 Mac 接入

| 项目 | Windows | Mac |
|---|---|---|
| SSH 服务 | 检测后按需安装 OpenSSH Server，避免重复安装 | 优先引导用户从系统设置开启远程登录 |
| 公钥 | 按管理员/普通用户及 sshd 配置选择路径，正确设置 ACL | 追加到目标用户 `~/.ssh/authorized_keys`，核验所有者与权限 |
| 管理员权限 | 入口请求 UAC，不将管理员口令写入脚本 | 用户本地确认必要的 sudo 或系统设置授权 |
| 桌面 | 交互式计划任务等需另测，不在 session 0 假验收 | 屏幕共享由用户开启；AI 截图与点击另测 |
| 保护现有配置 | 保留已有规则、公钥和服务用途 | 保留已有密钥、共享设置与用户权限 |

Windows 原生可选功能安装曾在<伙伴A>相关测试中长时间等待 Windows Update；必要时使用官方独立安装包，但版本和架构重新核实。PowerShell 5.1 使用纯 ASCII 或明确的 UTF-8 BOM，避免中文编码解析问题。多行脚本上传后用 `-File` 执行。→ [030-<伙伴A>案例与源码出处](030-%E5%8E%86%E5%8F%B2%E6%A1%88%E4%BE%8B%E4%B8%8E%E6%BA%90%E7%A0%81%E5%87%BA%E5%A4%84.md)

Mac 脚本若被 sudo 执行，要显式确认目标普通用户及家目录，不能把公钥误写入 root 的家目录。建议 `.ssh` 为 700、`authorized_keys` 为 600，并核对所有者和父目录权限。

验收：先保留可用的本地操作方式，成功验证公钥后再决定是否调整其他认证配置，避免锁出机器。

## 四、在 Air 提供下载

将经过检查的接入包复制到 Air 的独立暂存目录，用受限 HTTP 服务只提供本次文件：关闭目录浏览、不接收上传、绑定当次正确地址，设定退出时限。已知目标 IP 时可以进一步限定下载来源。

不要直接对整个 Downloads、家目录或含敏感文件的工作目录运行开放的文件服务。标准 `python -m http.server` 默认可能提供目录浏览，若采用它必须额外检查暴露内容与监听范围，不能当成案例受限服务的等价替代。

文件哈希用于核对传输一致性；哈希若也只由同一 HTTP 链接提供，不能单独证明来源可信。通过已建立的聊天或控制连接给出核对信息。

先从控制端验证 URL 返回真实压缩包而不是 HTML；用户下载后再用服务日志核对成功请求。端口及文件名以本次为准，案例端口 18768 不是固定要求。

验收：正确文件可下载，其他路径不暴露，记录下载服务截止时间。

## 五、接入验收与软件部署

按顺序验收，失败后在对应层排查：

1. **身份**：目标机本地显示的 SSH 主机公钥指纹与首次连接核对；不要默认关闭主机密钥校验。
2. **连接**：真实 SSH 登录，执行 `hostname` 和用户身份查询；仅端口探测不算通过。
3. **传输**：向明确的测试目录传输无敏感内容的文件，再读取核对。
4. **权限**：确认所需目录访问、管理员操作方式；不要自动配置通用免密 sudo。
5. **桌面**：需要 GUI 时单独核对截图完整、目标会话正确、点击有效；用户正在操作时协调执行。

AI 若在 mini4 而目标机只允许 Air，优先使用既有 Air 通路。例如 `ssh -J air <用户>@<目标IP>` 是连接结构示意，实际别名、账户和密钥需现场核对。

接入通过后先只读摸底：系统、架构、磁盘、已有软件、代理、业务系统和电源状态。按用户的软件清单部署，修改配置前备份。安装成功后用版本查询加真实启动/关键功能验证，不以安装器退出码代替全部验收。

Windows 的 session 0 与交互桌面分开验证；GUI 软件优先用当前登录用户的 Interactive 计划任务启动，安装所需提权与应用运行权限分别判断。截图要验证 DPI、会话和实际画面；只看到进程存在不能宣称窗口可用。OneDrive/Dynalist 的账号登录和同步、输入法候选及上屏都要单独验证；不能以打开登录页代替业务可用。微信输入法本次外层静默安装后仍需随附安装器完成用户启用，见 050；输入法组合与提交应在同一交互任务中完成，并在任务结束后读取验收文件，防止读取旧结果。Mac 的 SSH 进程环境不保证继承桌面登录态、钥匙串或 GUI 权限。遇到登录与权限问题先定位环境，不盲目重装软件。

### Mac 实测补充（2026-11-05）

- 下载先确认官方版本、架构和最低系统版本，核对完整长度、官方 SHA256 与压缩包/DMG 完整性，再在目标机验证签名。续传后仍要完整校验。一次下载损坏不足以确定代理或 CDN 是根因；控制端验签异常也不能直接判定目标包不可信，应核对目标机原生校验结果。
- OpenCode 本次使用官方 v2.2.5 arm64 ZIP，安装到目标用户 `~/.opencode/bin`，备份后配置 `.zprofile` 与 `.zshrc` 的 PATH。用目标用户 `zsh -lic` 验证版本，并通过 Ghostty 启动后检查父子进程链；模型认证和实际对话单独验收。
- 微信输入法本次以官方直包安装到 `/Library/Input Methods/WeType.app`。TIS 注册、启用与选择应通过当前桌面用户的临时 LaunchAgent 执行；UID 用现场 `id -u` 与控制台用户核对，不硬编码复制其他机器的 UID。以该 GUI 会话的当前输入源 ID 读回验证，不只看退出码或 SSH 的 defaults 输出。完成后卸载临时任务。
- 本次微信拼音 ID 为 `com.tencent.inputmethod.wetype.pinyin`，GUI 会话已读回选中；候选、中文上屏和重登后的持久性仍待验收。具体记录及脚本位置见 [080-Mac-Air接入与软件部署实测-20261105](080-Mac-Air%E6%8E%A5%E5%85%A5%E4%B8%8E%E8%BD%AF%E4%BB%B6%E9%83%A8%E7%BD%B2%E5%AE%9E%E6%B5%8B-20261105.md)。
- 系统升级按用户最终选择执行。本机保留 macOS 13.0；不能仅凭 8GB 内存断言 macOS 15 比 26 更快或更稳定。系统版本、应用兼容与安全维护情况需当次核对，不能把历史版本号当永久推荐。

## 六、撤销与恢复

临时维护结束：停止下载服务，删除本次新增的访问规则、到期任务和临时桌面任务；根据约定撤销本次公钥或关闭本次开启的服务。不要删除原有公钥和其他用途的 SSH 服务。

持续维护：公钥不设到期时间；只给临时下载服务设截止时间。记录密钥归属、账户、访问范围和 IP 依赖；重启后在可安排的时段验证一次连接。用户未要求长期改变睡眠或合盖行为时，不自动永久修改。

Mac 撤销时恢复本次调整的远程登录、屏幕共享及必要权限，按修改清单处理。Windows 恢复本次修改的规则和服务启动方式。操作前确认不存在其他正在依赖这些设置的维护任务。

验收：撤销后的访问行为符合约定，用户原有使用方式正常。

## 七、交付记录模板

每次维护完成后，新建当次记录，至少包含：

```text

控制端 / 下载服务机器：
目标名称 / 系统 / 架构 / 用户 / 当日 IP：
用户要求的软件与操作范围：

新增公钥的指纹与归属（不记录私钥）：
新增规则、服务与任务 / 临时或长期：
软件版本与配置备份位置：
SSH、文件传输、管理员权限、桌面分别如何验收：
下载服务是否停止：
连接与撤销方法：
未完成事项及真实限制：
```

有值得以后复用的坑和验证结论，按用户约定通过 `memnote` 投递；不要直接修改 Claude 维护的长期记忆仓。
