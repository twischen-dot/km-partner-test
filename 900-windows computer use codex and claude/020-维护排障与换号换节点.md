# 020 · 维护排障与换号换节点

## 一、定期维护清单（建议每月一次，或 VPS 有变更时）

| 项目 | 怎么查 | 注意 |
|---|---|---|
| 节点 IP 是否和 VPS 当前 IP 一致 | 对照 570 项目最新记录与登记表 | 换 IP 后**逐台**更新，见第三节 |
| Claude Pro / ChatGPT Plus 到期日 | 账号页面 | 过期的症状：Claude 报 401 或「organization has disabled」 |
| Claude Code 版本 | 在启动脚本环境里跑 `claude doctor` | <伙伴A>机交机后自动更新失败，一直停在 2.1.278（C6），不能认为它会自己更新 |
| Codex 版本 | `codex --version` | 启动时的更新提示已关闭；需要更新就手动替换整包 |
| 备份是否在跑 | 看 `知识库备份` 里最新快照的时间 | |
| 遗留的临时防火墙规则、计划任务 | `Get-NetFirewallRule`、`Get-ScheduledTask` | 只删自己建的临时项 |

## 二、故障分层判断

先分清是哪种问题：「我连不进去」（管理通道）和「他用不了 AI」（业务链路）是两件事，270 那次两件事恰好同时发生。

| 现象 | 最可能的原因 | 下一步 |
|---|---|---|
| Claude 和 ChatGPT **同时**连不上 | 共用的节点：VPS 换了 IP、宕机、到期，或 mihomo 没起来 | 看 `C:\ProgramData\mihomo\mihomo.log` 里 `dial <组名> ... i/o timeout` 指向哪个 IP |
| 7890 端口没有监听 | mihomo 没起来 | 查计划任务 `mihomo-proxy`、`keepalive.log`、配置语法 |
| 7890 在监听，日志报上游超时 | 节点不可达 | 对照 VPS 变更记录；用独立实例测试新参数 |
| 只有 Claude 不行，报 401 | token 失效或 Pro 到期 | 换 token（第四节），不要 logout |
| 只有 ChatGPT 不行 | Plus 到期或设备码登录失效 | 重新设备码登录 |
| 长任务跑到一半报 `ECONNRESET` | 长请求中途断线，GPT 正常的话网络本身是通的 | 重发，或把任务拆小（<伙伴A> 09-24 的情况） |
| 公司 OA 打不开 | 基本不是代理的问题，公司域名在直连名单里 | 先查公司网络 |
| sshd 在运行，但 SSH 超时 | 防火墙规则的来源 IP、本机 IP 或网络类别不匹配 | 看规则的地址过滤器，不要据此认为 SSH 没装 |

**证据分层**：服务在运行、端口开着、收到 HTTP 响应、模型真的回答了，是四种不同的证据，每一种只能证明对应的那一层。`CONNECT 200` 和 ChatGPT 网页返回 403 都不代表 AI 可用；最终以真实的最小调用为准。

**取证**：
- 用户在本机双击诊断脚本，生成文本报告后手动发回（参考 `270/scripts/20261020-original/bangge-check.cmd`，要改里面的节点地址和路径）。
- 需要远程时，用临时放行脚本：限定机器名和本机 IP，只放行当前操作端的 IP，**先注册到期自动删除任务，再放行**（参考 `bangge-connect.cmd`，写死了 10-20 的值，必须重新生成）。
- 读取配置时只输出选定的非敏感字段，不整份打印配置、环境变量或登录文件。

## 三、VPS 换 IP（或换节点）后更新客户端

270 的根因：10-17 VPS 换了 IP，<伙伴A>机的配置没跟着改，三天后两个 AI 同时断。

对登记表里的**每一台**机器：
1. 确认是同一台服务器，协议和密钥都没变，只是 IP 变了。如果密钥或协议也变了，就按新节点重填整段。
2. 复制正式配置为候选文件，只改 `server` 字段。
3. `mihomo.exe -t -d <目录> -f <候选文件>` 检查语法，确认退出码。
4. 用独立实例测试：换一套端口（例如 mixed-port 17890、controller 19090、DNS 11053），确认请求确实打到测试实例上（参考 `test-updated-node.ps1`）。
5. 备份正式配置为 `config.before-<事由>-<日期时间>.yaml`，写入改动，通过 controller 热加载，或者按守护循环的方式重启。
6. 确认新请求确实走了新地址；失败就恢复备份并重新加载。
7. 做第 010 手册第 10 步的真实桌面验收，然后更新登记表里的「节点及 IP」和「最近验收」。

不要为了修 AI 改成全局代理，兜底继续保持 `MATCH,DIRECT`。

**没有远程通道的机器**：只能让用户在本机操作。提前准备好「一键替换 IP」的脚本，带备份、语法检查和失败回滚，让用户双击运行。这个通用脚本**还没有开发和验收**，`apply-node-ip.ps1` 写死了新旧 IP，只能作为参考。

## 四、换账号

**Claude**
1. 用新账号在任意一台能用 Claude 的机器上运行 `claude setup-token`，得到新 token。
2. 用户运行 `set-claude-token.sh`（改成这台机器的地址），按提示粘贴。看到 `TOKEN_OK` 和 `SAVED` 才算成功。如果验证没通过，脚本会删掉旧 token 文件，这时 Claude 会暂时用不了，重新跑一次即可。
3. 成功后，到旧账号的 claude.ai 设置里吊销旧 token。

**Codex**
1. 在这台机器上重新做一次设备码登录（WMI 启动，进程带代理环境变量），用户在手机上用新账号完成。新登录会覆盖 `auth.json`。
2. **不要运行 `codex logout`。**
3. 注意：注册 OpenAI 账号可能要求手机号，不接受 +86 号码。

## 五、拆除远程通道（交给别人时，最后一步做）

拆完之后就再也连不进去了，所以**先验收、记录，再拆**。在目标机上：
1. `Stop-Service sshd; Set-Service sshd -StartupType Disabled`
2. 删除我们加的防火墙规则（如 `sshd-lan` 和各种临时规则）。
3. 从 `administrators_authorized_keys` 或 `authorized_keys` 里删掉我们的公钥。
4. 删除我们的计划任务（如 `<owner>-run-in-session`、验证任务、到期清理任务）。
5. 删除临时目录和测试文件；`C:\ProgramData\claude-entry\` 里只保留 `claude-local.cmd`、`codex-local.cmd`、`vault-backup.ps1`、图标和说明文件。
6. 检查 `C:\Users\<user>\.ssh\` 里是否有我们留下的私钥或 config，有就删掉，并在对应服务器上撤销公钥。

**保留**：`C:\ProgramData\mihomo\`、计划任务 `mihomo-proxy` 和 `vault-backup`、`知识库备份` 目录。

在我们这边：删掉 Claude Code `/permissions` 里给这台机器加的放行规则，处理掉专用于这台机器的私钥，并更新登记表。

> <伙伴A>机的现状：到 10-20 为止，原有的 sshd、公钥和 9-27 加的规则都还在，只撤销了当天的临时规则。是否彻底拆除还没有决定。

## 六、和 Claude Code 自动模式的安全检查打交道

在 600 项目里，以下操作被自动模式拦截过。**不要绕过**，比如换一台机器做、换个工具做同一件事：
- 注册 SYSTEM 身份的开机任务、在局域网开 HTTP 分发服务：由用户自己用 `!` 前缀运行。
- AI 经手 Claude token：改为用户运行脚本、从 stdin 输入。
- 从境外服务器反连别人的电脑：方案作废。
- 批量卸载软件：用户通过 `/permissions` 为这台机器加放行规则。规则写法：`Bash(ssh user@ip *)`；scp 规则不要以 `:*` 结尾；用 `&&` 串起来的命令不会匹配规则，要一条一条发。
