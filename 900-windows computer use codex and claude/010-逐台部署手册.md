# 010 · 逐台部署手册

**读者**：动手的人或 AI（Claude / Codex，经 mini4 或 Air 操作）。
**规则**：每一步都有验收标准，验收没过就不要往下走。坑的编号（W1、N3、C1 等）指 `600/030-坑表.md`，详细症状在那里。

## 通用约定（先读）

1. **SSH 进 Windows 落在 session 0，不是用户桌面。** 装 GUI 程序、跑 Codex 沙箱、截屏、做「用户会怎么用」的测试，一律通过交互式计划任务放进 session 1（`scripts/run-task.ps1`）。session 0 里的失败很多是假阴性（W1）。
2. **PowerShell 5.1 脚本一律纯 ASCII，scp 上传后用 `powershell -NoProfile -ExecutionPolicy Bypass -File xxx.ps1` 运行，不要内联。** 内联命令会被 zsh → ssh → Windows shell → PowerShell 层层转义吃掉（P2）。中文超过一两个词时，写进 UTF-8 文本文件当数据读入，用 `-Encoding UTF8`（D1）。
3. **测网络用 `curl.exe`**，别用 PowerShell 的 `curl` 别名。
4. **凭据不经 AI 的手。** token 由用户自己输入；节点参数、私钥、token 不进聊天、不进知识库。
5. **改配置前先备份，改完先验证。** 失败就恢复备份。
6. **用户在机器前操作时，不要远程点击**（坐标会落到新弹出的窗口上）。

## 第 0 步 · 定方案、登记

- 按 `000-README.md` 回答五个问题，在登记表新增一行。
- 准备：节点参数文件（Mac 本地）、这台机器要直连的国内域名清单、两个账号。
- **验收**：登记表这一行除「最近验收」外都已填好。

## 第 1 步 · 建立管理通道（用户在机器前做一次）

1. 用户以管理员身份安装 OpenSSH Server（MSI 版）。
2. 把操作端公钥放进 `C:\ProgramData\ssh\administrators_authorized_keys`（管理员账号）或 `C:\Users\<user>\.ssh\authorized_keys`（普通账号）。
3. 防火墙规则**只放行操作端的来源地址**，例如当前 Air 的局域网 IP。注意网络类别（Public / Private）和本机地址条件也会让规则失效，270 就是这样连不进去的。
4. 操作端连接：在同一局域网时，从 mini4 走 `ssh -J air <user>@<Windows IP>`。首次连接要核对主机指纹。

远程通道的长期去留：
- **别人的电脑**：交机前拆除，见 020 第五节。
- **你自己的电脑**：可以保留局域网 SSH（只放行固定来源）。如果想像 Air、Mini 那样从 US2 随时进来，需要 Windows 主动建立到 US2 的反向隧道。**这条路在 Windows 上没有实测过**，要单独设计和验收，不在本手册范围内。

**验收**：`ssh <user>@<ip> hostname` 返回机器名。

## 第 2 步 · 摸底（只读）

记下：系统版本号、内存和磁盘（C、D 是否同一块物理盘）、BitLocker、杀毒软件、已装软件、开机自启项、默认浏览器、桌面图标、输入法（有没有五笔）、本地用户、OEM 管家类进程。

**验收**：能说清哪些软件是用户在用的，哪些是推送来的。用户在用的软件一个都不动。

## 第 3 步 · 代理（mihomo）

1. 在 Mac 下载 mihomo Windows 版和 `geosite.dat`、`geoip.metadb`，校验后传到 `C:\ProgramData\mihomo\`。
2. 以 `scripts/mihomo-config-template.yaml` 为底稿：
   - **第 1 层，置顶直连**：把模板里的<伙伴A>公司域名（`<公司域名1>`、`<公司域名2>`、`<公司域名3>` 等）**换成这台机器自己的**；微信、QQ、支付宝、银联、各大银行保留。
   - **第 2 层，必须走代理**：anthropic、claude.ai、claude.com、claudeusercontent、openai、chatgpt、oaistatic、oaiusercontent、`GEOSITE,openai`，以及 Google、GitHub、Cloudflare 等。
   - **第 3 层**：`GEOSITE,google`、`GEOSITE,geolocation-!cn` 走代理。按类别放行，不逐条列域名（N3）。
   - **第 4 层**：`GEOSITE,cn`、`GEOIP,CN,no-resolve` 直连。
   - **兜底**：`MATCH,DIRECT`，不可更改。
3. 节点段（`proxies`）从 Mac 本地的节点文件填入，`server` 必须是**当前** VPS IP。推荐把 AI 域名单独放进一个组（<伙伴A>机自 09-27 起叫 `CLAUDE-US`），这样以后可以给 AI 和其他境外流量分别指定节点。
4. **先测试再上线**：`mihomo.exe -d C:\ProgramData\mihomo -f config.new.yaml -t`，看到 `test is successful` 后才替换 `config.yaml`，旧文件保留为 `config.prev.yaml`（N5）。
5. 开机自启：用 `scripts/register-mihomo.ps1` 注册 SYSTEM 身份的开机任务 `mihomo-proxy`，运行守护循环 `scripts/mihomo-keepalive.ps1`。Claude Code 的自动模式会拦截注册 SYSTEM 任务，所以**由用户自己以 `!` 前缀运行**（坑表 A 节）。
6. 系统代理（给浏览器用）：通过 run-task 运行 `scripts/set-proxy.ps1`，指向 `127.0.0.1:7890`，并设绕过名单。mihomo 万一挂了，公司系统也不会跟着断。
7. 为了不让用户以后误按，controller 只监听 `127.0.0.1:9090`，最好设管理口令（口令不写进知识库）。

**验收**：
- 杀掉 mihomo 进程，10 秒内自动恢复。
- 日志里公司域名、微信走 DIRECT；`api.anthropic.com`、`chatgpt.com`、`auth.openai.com` 走 AI 节点组。
- 对照测试：
  ```powershell
  $url = 'https://api.anthropic.com/?cb=' + [Guid]::NewGuid().ToString('N')
  curl.exe -q --noproxy '*' --connect-timeout 8 --max-time 20 -I $url
  curl.exe -q --noproxy localhost,127.0.0.1 --proxy http://127.0.0.1:7890 --connect-timeout 8 --max-time 20 -I $url
  ```
  直连应失败或返回 403；经代理应拿到 Anthropic 的 HTTP 响应（09-19 实测 405，10-20 实测根路径 404，取决于请求方法和路径）。这一步只证明网络层通了，不证明 AI 可用。
- **不要**用 ip-api 之类的网站测出口 IP：兜底是直连，看到本地 IP 是正常的（N6）。

## 第 4 步 · 电源（笔记本）

插电时不睡眠、不关屏、合盖不做任何动作；电池模式保持原样。联想把「合盖动作」隐藏了，要先 `powercfg -attributes SUB_BUTTONS LIDACTION -ATTRIB_HIDE`，见 `scripts/lid.ps1`。powercfg 输出是中文，只能按 GUID 和十六进制值解析（P4）。

**验收**：插电合盖后，从操作端仍能 SSH 进去。

## 第 5 步 · Obsidian 与知识库

1. Obsidian 安装包（NSIS）在 session 0 会卡住，在 Limited 权限的计划任务里也会静默失败。**直接让用户在机器前点击安装**，选「为所有用户安装」。
2. 建库目录，例如 `D:\<名字>的知识库`。写好 `obsidian.json`，让 Obsidian 启动时直接打开这个库。
3. 库的来源，三选一：
   - **独立本地库**（<伙伴A>机实测）：最稳，推荐先用这种。
   - 从你的主库拷一部分资料进去：只拷需要的目录，并在登记表注明「副本，不回写」。
   - 让 Windows 直接打开 iCloud 里的主库（iCloud for Windows）：**未实测**，而且会和 mini4 的入库队列、Air 推 GitHub 的流程同时写同一个库，冲突风险高。不推荐。

**验收**：用户双击 Obsidian，直接进入这个库。

## 第 6 步 · Claude Code

1. 在 Mac 下载 Windows 版 `claude.exe`，校验签名链（签名公钥指纹、manifest 签名、sha256），三项都对上再传到 `%USERPROFILE%\.local\bin\claude.exe`。
   - 另一种做法是在 Windows 上用官方安装脚本 `irm https://claude.ai/install.ps1 | iex`，先在同一个 PowerShell 窗口设好 `$env:HTTPS_PROXY='http://127.0.0.1:7890'`。**这条路径在本项目里没有实测过**，用了要记录结果。
2. 启动脚本：把 `scripts/claude-local.cmd` 放到 `C:\ProgramData\claude-entry\`。它在进程内设置 `HTTPS_PROXY` / `HTTP_PROXY` / `NO_PROXY`，从 `%USERPROFILE%\.claude\oauth-token` 读取 `CLAUDE_CODE_OAUTH_TOKEN`，再启动 claude.exe。
3. 预置首次启动状态：`scripts/claude-preseed.ps1` 写 `.claude.json`（onboarding 已完成、主题、信任库目录；`D:\…` 和 `D:/…` 两种写法都写，C5）。
4. 粘贴键：`scripts/paste-keys.ps1` 第 2 部分写 `keybindings.json`，把 Ctrl+V 绑到 `chat:imagePaste`。
5. **token 由用户自己放**：
   - 用户在任意一台能用 Claude 的机器上运行 `claude setup-token`，用这台 Windows 要用的账号登录，得到 `sk-ant-oat01-…`。
   - 运行 `scripts/set-claude-token.sh`：token 从 stdin 输入、不回显，**先在目标机上真实调用一次 Claude，通过了才保存**，文件权限只给本人。原脚本写死了<伙伴A>机的地址和用户名，复用前要修改。
   - 注意：token 的优先级高于 `/login`。如果留下一个坏的 token 文件，就会一直报 401（C1）。粘贴时终端可能把 token 折成两行，正常长度是 108 字符（C2）。
6. auto 模式：给别人用的机器，建议交付时切回普通模式（Shift+Tab），或者当面讲清楚它会不经确认就执行命令、安装软件。

**验收**（在 session 1 里跑）：在库目录执行 `claude -p`，能读出测试笔记里的暗号，写出的文件在磁盘上看得到。

## 第 7 步 · Codex（ChatGPT）

1. 下载 Windows 整包，**保留目录结构**，解压到 `%USERPROFILE%\.local\codex\`。
2. 写 `%USERPROFILE%\.codex\config.toml`：
   ```toml
   check_for_update_on_startup = false

   [windows]
   sandbox = "unelevated"

   [projects."D:\\<名字>的知识库"]
   trust_level = "trusted"
   ```
   不写 `sandbox`，所有命令都会报 `blocked by policy`（C3）。用 `codex doctor` 确认。
3. 登录：通过 WMI 的 `Win32_Process.Create` 启动 `codex login --device-auth`，进程要带代理环境变量（`scripts/codex-login-local.ps1`）。直接在 SSH 里跑的话，会话一断就停止轮询（C4）。把网址和设备码发给用户，用户在手机上用**这台机器要用的 ChatGPT 账号**完成授权。
4. 启动脚本：把 `scripts/codex-local.cmd` 放到 `C:\ProgramData\claude-entry\`。

**验收**：在 session 1 里用 `codex exec` 读暗号、写文件，都成功。session 0 里报 `0xC0000142` 是假阴性。

## 第 8 步 · Windows Terminal 与桌面图标

- 不要就地修改 WT 的 `settings.json`（PowerShell 5.1 解析不了里面的注释）。先备份为 `.orig`，再写一份干净的最小配置：`defaultProfile` 指向 Claude、`copyOnSelect: true`、`launchMode: maximized`，关掉 WSL / Azure / PowerShell Core 等配置来源，隐藏 PowerShell 和 cmd。
- 两个配置写在 Fragment 文件里（`%LOCALAPPDATA%\Microsoft\Windows Terminal\Fragments\…`），**使用固定 GUID**，`startingDirectory` 设为库目录，`suppressApplicationTitle: true`，字体 Cascadia Mono 16 号，各自设图标。
- 粘贴：用 `scripts/paste-keys.ps1` 第 1 部分。WT 的 Ctrl+V 贴文字，Alt+V 把 0x16 发给程序用来贴图（T1）。结果是两个 AI 都用 Ctrl+V 贴文字、Alt+V 贴图。
- 桌面放两个快捷方式：「Claude」= `wt.exe -M`，「ChatGPT」= `wt.exe -M -p <GPT 配置名>`。再放一份「连不上怎么办.txt」。

**验收**：用户亲手在两个窗口里各贴一次文字、贴一次图。

## 第 9 步 · 库的规矩与备份

1. 库根目录放 `AGENTS.md`（模板：`scripts/AGENTS.md`，把「<伙伴A>」换成使用者），`.claude\CLAUDE.md` 里只写一行 `@../AGENTS.md`。点目录在 Obsidian 里不显示。
2. 库根目录放 `AI记忆.md`（模板：`scripts/AI记忆-模板.md`）。这是两个 AI 共用、人也能看能改的记忆，AI 只追加不改旧行。
3. 备份：`scripts/vault-backup.ps1` 配一个计划任务，身份是本人，登录类型 **S4U**（不弹窗，用户没登录也会跑），每小时一次，登录时再跑一次。
   - 备份内容：知识库本体 + `_claude-memory\`（`%USERPROFILE%\.claude\projects\…\memory\`）+ `_codex-memory\`（`%USERPROFILE%\.codex\memories_*.sqlite` 及 -shm / -wal）。
   - 位置：`C:\Users\<user>\知识库备份\`，再用 robocopy /MIR 镜像到 D 盘。C、D 往往是同一块物理盘，只能防「重装 C 盘」，防不住整机丢失（R4）。要防整机丢失，需要用户自己登录 OneDrive 之类的云盘。
   - 文件指纹没变就不生成新快照；保留最近 20 份，其余保留 30 天。

**验收**：
- 用英文问两个 AI「改文档时要遵守什么」，它们都用中文复述规矩。
- 手动触发两次备份：第一次产生快照，第二次不产生。
- 故意在库里新建一个测试文件再删除，确认能从快照里找回。用脚本删除是永久删除，不进回收站（D3）。

## 第 10 步 · 真实桌面验收（端到端）

在 session 1 里，用现有登录各发一个最小请求（参考 `270/scripts/20261020-original/verify-ai-desktop.ps1`）：

```text
Reply exactly NETWORK_OK. Do not use any tools.
```

- Claude：JSON 输出 `is_error=false`，`result=NETWORK_OK`。
- Codex：最终回复为 `NETWORK_OK`。
- 原脚本的子进程退出码采集有缺陷，会输出空值，**不要把空值当成 0**，以回答内容为准（270/030 第三节）。

然后让用户亲手打开两个桌面图标，各问一句中文，用自己常用的输入法（五笔 / 微信输入法）打字。

**验收**：两个 AI 的回答都正确；中文输入正常。

## 第 11 步 · 清理 OEM 推送（按需）

联想电脑管家这类软件会推送 360 浏览器、画报，还会改默认浏览器（L1）。先删开机自启项、结束进程，再运行卸载程序。挽留窗口要一页页点完，最后一页的「体验新版」要点 ✕。默认浏览器只能由用户在「设置 → 默认应用」里改。推送开关由用户手动关。

## 第 12 步 · 收尾与登记

1. 删除测试文件和测试任务。`C:\Users\<user>\.<owner>\` 这类临时目录里如果有截图、安装包，确认后删除。
2. 远程通道：按第 1 步的决定，保留（并在登记表写明范围）或拆除（020 第五节）。
3. 在登记表填「最近验收」日期；装机中新遇到的坑，补进本目录或 600/030 坑表。
4. 交给别人使用时，当面讲四句话：
   - 双击桌面「Claude」「ChatGPT」就能用；Ctrl+V 贴文字，Alt+V 贴图。
   - 它们能读写知识库，改文档时会另存新版本；你让它读的内容会发送给 Anthropic / OpenAI。
   - 知识库每小时自动备份到 `知识库备份` 文件夹。
   - 连不上时，先看桌面的「连不上怎么办.txt」。
